DATASET ATLAS · AIDEV

Five coding agents, 933K pull requests, one collaboration experiment inside real repositories.

AIDev collected 932,791 agentic PRs from GitHub, spanning 116,211 repositories and 72,189 developers, with data cut off on 2025-08-01. It is not a leaderboard or an answer key, but a reusable observational substrate: it joins agent submissions, human reviews, follow-up fixes, and event timelines so researchers can ask real-world questions about adoption, quality, and risk.

02 / WORKFLOW

The full loop of an agentic PR.

AIDev's structure follows the real GitHub collaboration workflow. The path in Figure 1 explains why the dataset includes PRs, comments, commits, issues, and timelines together.

01

Take an issue

The agent is assigned an issue in a real project and receives task context and acceptance goals.

02

Generate a patch

It locates files in the repository, changes the implementation, and runs available checks or tests.

03

Open a PR

It submits a pull request with a title, description, and scope, entering the public collaboration process.

04

Receive human review

Maintainers comment, request changes, or approve; these judgments become first-hand signals of quality and risk.

05

Follow up and fix

The agent responds to comments through follow-up commits and replies, keeping human-agent collaboration moving.

Note: not every coding agent supports handling review comments. "Reviewed" and "review resolved" are therefore different kinds of evidence and should be analyzed separately.

04 / RESEARCH AGENDA

What does it make measurable?

The paper lays out five research agendas. These are not conclusions built into the dataset, but the next set of empirical questions AIDev is meant to support.

01

Adoption & practice

Who uses coding agents? How do adoption paths differ between newcomers and experienced developers? How does penetration vary across repositories and ecosystems?

02

Patch characteristics

How do agentic PRs change code: lines added or removed, files touched, and the balance of refactoring and reuse? Do they follow project conventions and CI checks?

03

Testing behavior

How often do agents contribute tests? When tests are missing, do developers add verification through follow-up commits or linked PRs?

04

Review dynamics

Which concerns dominate review: correctness, style, security, or testing? Which comments can agents resolve, and which remain difficult?

05

Failure modes & risk

How do common defects emerge? Can early signals predict rejection or review cost? Which changes eventually reach production and persist?

KEY INSIGHT

Roughly four in five AI PRs are eventually merged.

But acceptance is not the same as a clean pass: 214 of 475 merged PRs (45.1%) were revised before merge.
